# ДЗ-2. Параллелизм

База это train.py из шаблона, 6830 токенов/с. Короткие раны по 90 секунд, в каждой серии ранов база мерилась заново, ускорение считаю к ней. Разброс базы между сериями около 3%, меньшие разницы считаю шумом.

| шаг | ускорение |
|---|---|
| шаблон, SDPA, батч 32 с накоплением 2 | 1.00 |
| FA2 | 1.04 |
| FA2 и packing | 3.00 |
| добавил liger | 3.51 |
| батч 64 без накопления | 3.64 |
| итог на 300 секунд | 3.91 |

## Packing и padding-free

- padding-free 2.61, packing 3.00
- главная потеря в шаблоне это паддинг, модель считает его наравне с текстом
- у packing в микро-батче около 16 тыс. токенов, у padding-free около 2.8 тыс., поэтому packing лучше загружает GPU

## SDPA и FlashAttention2

- FA2 сам по себе даёт 4%, с паддингом он убирает лишнее только в attention
- FA2 нужен для packing и padding-free, он считает attention по каждому абзацу отдельно

## Liger

- один 0.99, но экономит 14 GiB памяти
- с packing ускоряет на 17%, с 3.00 до 3.51
- с padding-free замедляет на 10%, с 2.61 до 2.36
- скорее всего дело в размере микро-батча, liger считает cross-entropy кусками, и на большом микро-батче его накладные расходы окупаются

## torch.compile

- с паддингом первый шаг вместе с компиляцией занял 116 секунд, замер не успел начаться
- padding-free и liger на 240 секунд: компиляция около 150 секунд, потом 2.46 против 2.36 без неё, за 5 минут не окупается
- с packing и liger loss стал NaN

## Batch size и gradient accumulation

- батч 64 без накопления в шаблоне не влезает в память
- packing и liger: батч 32 с накоплением 2 даёт 3.51, батч 64 даёт 3.64, батч 96 даёт 3.82, батч 128 не влез
- padding-free и liger: рост до батча 384, там 3.45
- потолок около 27 тыс. токенов/с
- на 300 секунд батч 96 дал 3.98, но всего 169 шагов при warmup 200, val loss 7.131 хуже базы с 6.659
- батч 64 дал 3.91, 246 шагов и val loss 6.165, его и взял в итог

## Activation checkpointing

- один 0.82, память с 41 до 17 GiB
- с packing, liger и батчем 64 даёт 3.13 против 3.64, память с 42 до 10.5 GiB
- скорость уже в потолке, поэтому сэкономленная память не помогает

## Activation offloading

- с SDPA падает с ошибкой
- с FA2 и padding-free 0.42 против 2.61, в 6 раз медленнее

## Итог

- train.py: FA2, packing, liger, батч 64 без накопления
- 26733 против 6830 токенов/с, S = 3.91
- val loss 6.165 против 6.659, пик памяти 41.9 GiB против 41.2
- все раны в results/table.md

## Кольцевые коммуникации

- ring_reduce_scatter: p-1 шагов, каждый процесс отправляет часть соседу справа и прибавляет то, что пришло слева, в конце у процесса r полная сумма части r
- ring_all_gather: p-1 шагов, каждый процесс передаёт дальше по кругу часть, полученную на прошлом шаге
- ring_all_reduce: reduce-scatter и потом all-gather, 2(p-1) шагов
- отправка через isend, приём через recv, поэтому процессы не ждут друг друга по кругу
- проверка в communications.ipynb проходит на 2 и 4 процессах

## Выводы

1. Главная потеря скорости это паддинг, packing даёт ускорение в 3 раза.
2. Эффект зависит от сочетания: liger один ничего не даёт, с packing ускоряет на 17%, с padding-free замедляет на 10%.
3. Батч больше 64 почти не ускоряет и за 5 минут даёт мало шагов.
4. Checkpointing, offloading и compile здесь только замедляют.
